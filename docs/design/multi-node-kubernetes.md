# Многонодовая Kubernetes-лаборатория

Milestone 10A использует один control plane и два worker kind на одном runner Ubuntu.
Все три узла делят CPU, RAM, диск и ядро Linux. Каждый сценарий получает отдельные
кластер и kubeconfig. Приложение устанавливается из существующего chart lab-api.
Две реплики используют мягкое распределение по hostname, чтобы пережить потерю
одного worker. PostgreSQL, Kafka и observability не входят в этот стенд.

Workflow запускает группы последовательно на стандартных runner. Фактические CPU
и память записываются в runner.json. Обычные группы используют kindnet. Сетевая
группа использует отдельный кластер с Calico и проверяет HTTP по ClusterIP, чтобы
отличить фильтрацию от сбоя DNS. Входящая политика сохраняет исходящий DNS.
Процедура для независимых VM описана отдельно.
