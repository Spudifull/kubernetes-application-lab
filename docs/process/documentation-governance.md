# Управление документацией

Этот документ определяет, где хранится долговечное техническое знание и как различаются `Current`, `Target`, решение и доказательство.

**Состояние: Current.**

## Один факт — один владелец

Нормативное утверждение поддерживается в одном каноническом месте.

| Каталог | Ответственность |
|---|---|
| `architecture/` | устойчивые границы нескольких частей проекта |
| `design/` | контракт одной ограниченной области |
| `verification/` | воспроизводимые проверки и результаты |
| `engineering/` | практические инструкции |
| `process/` | правила работы и документирования |
| `adr/` | причины принятых решений |
| `roadmap.md` | незавершённая работа |

Если правило уже определено в каноническом документе, другой документ ссылается на него, а не создаёт вторую нормативную копию.

## `Current` и `Target`

`Current` описывает фактическое состояние кода и исполняемой конфигурации.

Когда утверждение относится к поведению, одного файла недостаточно: состояние должно иметь воспроизводимую проверку соответствующего уровня.

`Target` используется для уже выбранного направления, которое реализовано не полностью. Он не должен создавать впечатление готовой возможности.

## ADR

ADR создаётся после принятия решения владельцем. Допустимые статусы: `Accepted`, `Superseded`.

ADR хранит контекст, выбор, альтернативы и последствия. Он не заменяет текущий контракт и не является доказательством реализации.

## Доказательства

`docs/verification/` отвечает на вопрос «чем подтверждается это свойство?».

Подготовленный сценарий без фактического выполнения получает статус `Prepared`. Статус `Passed` допустим только при наличии зафиксированного выполнения с достаточными сведениями о ревизии и среде.

## План развития

`docs/roadmap.md` использует состояния `Done`, `Current`, `Next`, `Later`, `Blocked`.

Git хранит хронологию изменений. Не создавать отдельные журналы итераций, если они не нужны для понимания действующего контракта.

## Язык

Для русскоязычных документов обязательны [правила разработки](../../CONTRIBUTING.md).

Названия технологий, Kubernetes kinds, поля API и идентификаторы сохраняются без перевода. Остальная проза должна использовать естественные русские инженерные термины и не превращаться в смесь английских существительных с русским синтаксисом.
