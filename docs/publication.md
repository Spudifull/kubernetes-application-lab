# Публикация после отдельного одобрения

Этот каталог подготовлен как независимый снимок без .git. Проверки подготовки и частные детали аудита хранятся вне него. Порядок ниже относится к подготовке нового репозитория владельцем, а не к обычному клонированию. Первоначальная загрузка выполняется только в Private; открытие Public требует отдельного решения. Повторно выполнять git init и начальный commit после клонирования не нужно.

Проверить резервную приватную копию, audit report и manifest; повторить сканирование кандидата. Имена repo проверяются повторно непосредственно перед созданием: прежний 404 не резервирует имя и не гарантирует отсутствие скрытого private repo.

После разрешения владельца, из корня данного снимка:

```sh
git init -b main
git add .
git commit -m "Первый публичный релиз Kubernetes Application Lab: этапы 1–8"
```

Затем создать Spudifull/kubernetes-application-lab с visibility Private, без автоматически созданных README/LICENSE, добавить только новый origin и push -u origin main. Не отправлять исходные branches/tags; не использовать --mirror, --all или --force. Просмотреть файлы в GitHub и проверить свежий clone. Только после отдельного одобрения сменить visibility на Public.

До git init любая Task-команда может требовать явного REVISION=publication-candidate: Taskfile вычисляет revision из Git. Пример: task observability-helm-lint REVISION=publication-candidate. Эти временные образы не являются историческими проверенными образами. Генерируемые .local-* не должны входить в начальный commit. Кластеры, PostgreSQL/Kafka/PVC для миграции не изменяются.
