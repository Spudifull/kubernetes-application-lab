# ADR-0002: Разделение управления инфраструктурой и приложением

**Статус:** `Accepted`  
**Дата:** 2026-10-04

## Контекст

Terraform, Helm и GitOps могут изменять ресурсы одной системы. Если несколько инструментов независимо управляют одним объектом, становится неясно, какой из них должен восстановить его состояние после изменения или сбоя.

## Решение

Разделить ответственность по уровням:

| Инструмент | За что отвечает |
|---|---|
| Terraform | Виртуальные машины, сеть, диски и другая базовая инфраструктура. |
| Helm | Описание и установка Kubernetes-ресурсов приложения. |
| GitOps | Выбор и поддержание нужной версии конфигурации окружения, в том числе через Helm. |

**Один Kubernetes-ресурс не должен одновременно управляться Terraform и Helm как двумя независимыми источниками желаемого состояния.** GitOps задаёт, какую конфигурацию Helm нужно применить и не создаёт параллельный способ управления тем же `Deployment`.

## Почему так

Управление `Deployment` и `Service` непосредственно через Terraform смешало бы создание инфраструктуры с выпуском приложения. Одних YAML-манифестов достаточно для небольшого опыта, но они не решают задачу управляемых выпусков и повторяемой установки. Полный отказ от GitOps оставил бы без проверки согласование Git и работающего окружения.

Выбранная схема позволяет изучать каждый уровень отдельно.

## Последствия

Инфраструктуру можно менять без пересборки приложения, а приложение — выпускать без пересоздания виртуальных машин. При этом требуется явно определять, какой инструмент изменяет конкретный ресурс, особенно при установке уже существующих объектов.

Изменение этого разделения должно оформляться новым архитектурным решением.
