# План развития Kubernetes Application Lab

План описывает незавершённую работу. Реализованные контракты принадлежат профильным документам, а доказательства поведения — `docs/verification/`.

## Done: этап 1 — минимальный Kubernetes workload

Реализованы Go API, обязательные диагностические маршруты, метрики, ограниченное по времени завершение, многоэтапный образ без Go toolchain, локальная конфигурация `kind`, `Deployment`, `ClusterIP Service`, три probes, requests/limits и единый интерфейс `Taskfile.yml`.

Для исходной реализации были выполнены серверная проверка манифестов, развёртывание, запрос через Service proxy, удаление Pod, автоматическое восстановление и наблюдение перехода readiness при `SIGTERM`.

## Done: реализация Milestone 1.1

Выполнены очистка устаревших проектных навыков и локальных артефактов, маркировка изменённой сборки суффиксом `-dirty`, общая блокировка прикладных маршрутов во время завершения, закрепление образа узла Kubernetes v1.34.0 и создание внутрикластерной минимальной проверки через DNS-имя `Service`. Исправлена регистрация удаления временного клиентского Pod.

Предварительный прогон на изменённом дереве `f9e7b663af7a-dirty` сохранён в отчётах. Чистые повторы 24 октября подтвердили сетевой путь, восстановление Pod и завершение после `SIGTERM`; соответствующие отчёты имеют статус `Passed`.

Ревизии release `1` → `2` → `3`; [отчёт](verification/helm-install-upgrade.md) имеет статус `Passed`. Исторические предварительные прогоны сохранены в нём.

Доказательства Milestone 1.1 и Milestone 2 закрыты профильными отчётами в [каталоге проверок](verification/README.md#milestone-11-и-milestone-2).

## Done: реализация этапа 3 — обновление и завершение

Добавлены профиль двух реплик с явной стратегией, ограниченный лабораторный маршрут `/work`, временный внутрикластерный клиент со статистикой и команды для штатного обновления, неисправного образа и явного отката. Пользователь выполнил Go-проверки и предварительные сценарии на сборке `b01c0ad77c85-dirty`. Принятый запрос завершился ответом `200`, новая работа после начала завершения получила `503`; неисправный образ вызвал `ErrImageNeverPull`, а явный откат вернул две Ready-реплики. Предварительное обновление под нагрузкой завершилось с двумя ответами `503` из 1799 запросов. Последующие чистые повторы завершения и отката выполнены 24 октября, все три профильных отчёта имеют `Passed` в своих границах; прежние ошибки сохранены.

## Done: диагностика Milestone 3.1

Заголовок `X-Lab-Pod`, журналы отказа и раздельные наблюдения позволили исследовать чистый прогон `5a5290f9254b`: Helm revision 7 достигла двух Ready-реплик, но клиент получил три `503` из 1799 запросов. Все три связаны с отказом старых Pod после `SIGTERM`; прежние два `503` сохранены как отдельный неуспешный результат. На основании измерения добавлен ограниченный HTTP `preStop` до `SIGTERM` при неизменном `terminationGracePeriodSeconds: 20`. В чистом повторе на `c0cfd4e80fe8` Helm revision 9 достигла двух Ready-реплик, все 1799 запросов через `Service` завершились успешно, а прямые наблюдатели подтвердили отказ старых Pod после сигнала. Результат ограничен этим локальным опытом.

Завершение принятого запроса и неисправное обновление с откатом закрыты [профильными отчётами](verification/README.md#milestone-3). Прежние неуспешные опыты сохранены рядом с успешными; единичный локальный прогон не является гарантией отсутствия HTTP-ошибок.

## Done: Milestone 6 — PostgreSQL и состояние

Отдельный Helm release PostgreSQL, явный PVC, несекретная ConfigMap, создаваемый вне Git Secret, необязательный DB-профиль API, ограниченный Job миграции и команды для сценариев отказа и восстановления реализованы. Все пять профильных отчётов имеют статус `Passed` для выполненных локальных сценариев. В API использован чистый образ `df935dc5bf08`; повтор после commit `a57b85b` подтвердил исправление ошибочных подключений probes. При недоступной БД API сохранил `/livez: 200` и восстановился без перезапуска; отдельный release с неверным паролем дал `authentication_failed`, не затронув чтение рабочего API. На чистом образе `803c1bc2363c` отрицательный Job откатил создание контрольной таблицы после SQL-ошибки, следующий обычный Job успешно завершился. Из архива на хосте восстановлено `before-backup` в отдельную базу, основная сохранила `after-backup`, тестовая база удалена. Финальная регрессия базового профиля API на том же чистом образе при PostgreSQL `0/0` прошла, после опыта БД восстановлена до `1/1`. Дополнительные проверки отсутствующего Secret и отсутствующей таблицы выполнены 25 октября: после исправления ссылки на Secret и создания таблицы тестовый API восстановил готовность, основная база сохранила обе контрольные записи. Успешные результаты `go test ./...`, `go test -race ./...` и `go vet ./...` владелец предоставил 25 октября 2026 года. [Результаты Milestone 6](verification/README.md#milestone-6--postgresql-и-состояние) зафиксированы; можно переходить к следующему этапу в пределах подтверждённых свойств.
